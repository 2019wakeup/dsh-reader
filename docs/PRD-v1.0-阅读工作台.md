# PRD v1.0：砚读 · 阅读工作台

> 版本 v1.0 ｜ 2026-11-21 ｜ 作者：产品（lead）｜ 状态：已拍板（范围锁定）
> 前序：`docs/PRD-电子书阅读与概念标注.md`（v0.2 需求基线）、已交付插件 0.2.3

---

## 0. 一页结论

**1.0 的定义：一本能读完、能讲清、能带走的工作台。**

0.2.3 已经能读、能标、能解释、能复用。但它还不是 1.0，原因不是功能少，而是**闭环断在三个地方**：

1. **读完了带不走** —— 原 PRD 里 P0 的「导读 + 思维导图」整块没有交付，读完整本书仍然没有结构化产出。
2. **标注会静默消失** —— 跨粗体/行内代码的高亮直接丢；概念没有「出现位置」；文档改名就丢标注。
3. **日常使用不顺手** —— 没有设置页、没有键盘导航、没有导出/备份/迁移，PDF 中文取词未验证。

1.0 只做三件事：**补上导读**、**把标注做可靠**、**把数据做成资产**。翻译、概念图谱、手机端都不阻塞 1.0。

### 1.4 结论

1.0 不是"再加几个功能"，而是**补齐 0.2 欠下的三个 P0 契约**：导读、标注可靠性、数据可迁移。否则用户越用越不敢用——因为标注会丢、读完没产出、数据带不走。

## 2. 1.0 定位

**一句话**：把"读一本书"变成"读完这本书之后你拥有什么"。

| 维度 | 0.2.3 | 1.0 |
|---|---|---|
| 阅读 | 能打开 | 稳定、可调、键盘可用、中文 PDF 可标 |
| 标注 | 能标，可能丢 | 标了就在，改格式也不丢，可导出 |
| 概念 | 能解释、能悬停 | 可回看（出现位置）、可编辑、可合并 |
| 导读 | 无 | 章节摘要 + 全书主旨 + 可交互思维导图 + 导出 |
| 数据 | 单文件 | 指纹主键、自动备份、导入导出、可迁移 |

### 2.1 目标用户

- 主用户不变：用 DSH 做研究/学习/技术阅读的重度个人用户。
- 1.0 新增验收场景：**一本 300 页中文 PDF + 一本 EPUB + 一篇长 Markdown，连续 7 天真实使用**。

### 2.2 成功标准（1.0 发布时必须同时成立）

1. 读完一本书能在 60 秒内拿到一张可交互导读图，点击节点能跳回原文。
2. 任意标注（含跨粗体、改字号、重排、关掉再开）存活率 ≥ 99%。
3. 概念库任意条目能跳回它的每一个出现位置。
4. 改名/移动文档后，标注与概念一个不丢。
5. 导出 Markdown + JSON 可完整还原到另一台机器的空库。
6. 7 天 dogfood 中 0 次空白页、0 次数据丢失、0 次不可恢复错误。

- ❌ 社交分享、排行榜

## 4. 核心用户旅程

**J1 读完一本书**
打开 PDF → 读 → 标注/解释 → 点「生成导读」→ 章节摘要 + 主旨 + 3 个核心问题 + 导图 → 点节点跳原文 → 导出 SVG/Markdown。

**J2 回看一个概念**
概念库 → 搜索/按最近 → 点条目 → 看到定义/直觉/本书语境/例子/问答 → 点"出现于 3 处"跳到原文 → 在原文继续读。

**J3 换一台机器**
设置 → 导出（JSON + Markdown）→ 新机器导入 → 概念、标注、笔记、导读全部还原，文档按指纹重新绑定。

**J4 标注不丢**
跨粗体选中一句话 → 高亮 → 改字号/窗口大小 → 关掉重开 → 位置仍在；即使原文改动，标注显示"原文可能已变更"而不是消失。

**J5 追问**
概念卡点「追问」→ 问"和顺序一致性有什么区别"→ 答案展示并缓存；下次打开直接可见。

## 6. 关键设计决策

| 编号 | 决策 | 理由 | 代价 |
|---|---|---|---|
| D1 | **卡片栈**：父卡保留，子卡层叠，最多 3 层 | 嵌套是核心卖点，替换式会丢上下文 | 需要布局与焦点管理 |
| D2 | **锚点 v2**：多文本节点逐段包裹 + quote/occurrence/prefix/suffix 双保险 | 修复 F1；Web Annotation 成熟模式 | 实现比 `surroundContents` 复杂 |
| D3 | **词边界匹配**：拉丁 `\b`，CJK 不设边界，拉丁词长 ≥ 2 | 修复 F2；避免满屏假概念 | 少数专有名词需手动别名 |
| D4 | **出现位置由标注与解释共同写入**，不由全库扫描生成 | 低成本、可增量；避免每次打开全书扫描 | 未标注的出现不记录（可接受） |
| D5 | **内容指纹做主键**，路径仅用于显示与定位 | 修复 F6；支持导入导出 | 首开需算 hash（已计入 1.5s 预算） |
| D6 | **导读 map-reduce**：章节切块 → 摘要 → 全局大纲 → 树形导图；前端自绘 SVG | 不引第三方图库，保持主题一致 | 需自己做布局与折叠 |
| D7 | **导出三件套**：JSON（可迁移）、Markdown（可阅读）、SVG/PNG（可分享） | 数据资产化，不锁定 | 需定义稳定 schema |
| D8 | **设置写进插件自有 store + Config**，不新建 DSH 设置体系 | 降低耦合；用户可见 | 与 DSH 设置风格需对齐 |
| D9 | **Store v2 schema**：`{version:2, docs:{fingerprint:...}, concepts, guide}`，v1 自动迁移 | 1.0 前最后一次破坏性变更 | 需迁移测试 |

## 7. 数据模型与迁移

```ts
type StoreV2 = {
  version: 2
  docs: Record<string, {           // key = fingerprint
    path: string; size: number; mtime: number
    positions: { chapter?: number; page?: number; scroll?: number }
    annotations: Annotation[]
    guide?: Guide
  }>
  concepts: Record<string, Concept> // 增加 occurrences / aliases / qa
}
```

- 迁移：启动时检测 `version:1` → 备份 → 按路径建立首份 fingerprint 记录 → 写 v2 → 清 `__smoke__` 等空键。
- 失败：保留 v1 原文件，界面提示"迁移失败，已备份"，不阻塞阅读。
- 回滚：设置页"恢复上一版本"。

- 隐私：只发句段/章节；导出文件仅本机。
