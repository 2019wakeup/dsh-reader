# PRD：阅读工作台（代号「砚读」）

> 在 DeepSeek Harness 内嵌的电子书 / 文档阅读与概念标注系统
> 版本 v0.2 ｜ 2026-11-19 ｜ 状态：已评审（核心决策锁定）｜ 作者：lead

---

## 0. 一句话

把 DSH 变成一个**读得进去、看得懂、记得住**的阅读工作台：阅读界面占据主视野，AI 退到背景里，负责把你不懂的概念**就地解释、永久记下**，下次在任意文档里遇到时**不离开阅读就能想起**。

---

## 1. 背景与问题

### 1.1 现状

- 读 PDF / EPUB 的工具有很多（Zotero、MarginNote、微信读书、Readwise Reader），但它们的 AI 能力是外挂的：选中 → 跳转 → 复制到对话框 → 等回答 → 自己再记一遍。
- DSH 已经具备：文件预览、PDF 渲染、文档/指南侧栏、LLM 调用、翻译服务、持久化存储、插件机制。缺的是**一个把阅读本身当主界面的形态**。
- 传统阅读器的标注是"死"的：高亮颜色 + 批注文本，不会生长，不会复用，不会形成知识结构。

### 1.2 三个真实痛点

| 痛点 | 表现 | 后果 |
|---|---|---|
| **概念断裂** | 读到生词/术语，切出去搜，回来找不到原句 | 阅读节奏被打断，往往就不读了 |
| **解释不复用** | 同一个概念换一本书又不懂了，再问一遍 AI | 知识不沉淀，重复劳动 |
| **读完没结构** | 合上书只记得零散片段，讲不出全书脉络 | 无法迁移、无法复述、无法用于决策 |

### 1.3 机会

把"解释"从一次性的问答，变成**跨文档、可嵌套、可复用、可可视化**的知识资产。阅读器只是入口，真正的产品是那本**长在你身上的概念库**。

## 2. 目标与非目标

### 2.1 目标用户

- **主用户**：用 DSH 做研究 / 学习 / 技术阅读的重度用户（本 PRD 假定为个人自用、单机、桌面端）。
- **使用特征**：一次读 30–90 分钟；同时开 2–5 本书；常读中英混排的技术书、论文、教材。

【假设】首版不做多用户、不做团队协作、不做云端同步。

### 2.2 产品目标（可度量）

| 编号 | 目标 | 量尺 | 目标值 |
|---|---|---|---|
| G1 | 阅读不被 AI 打断 | 阅读会话中因"查概念"而离开阅读界面的次数 | 下降 ≥ 70% |
| G2 | 解释可复用 | 概念第二次出现时，hover 命中已有卡片的比例 | ≥ 80% |
| G3 | 概念有结构 | 存在父子/关联关系的概念占比 | ≥ 40% |
| G4 | 读后能复述 | 生成导读后，用户打开并交互过思维导图的比例 | ≥ 50% |
| G5 | 用得下去 | 周活跃阅读天数 / 周 | ≥ 3 天 |

**北极星指标**：每周「概念卡命中次数」——它同时衡量了阅读量、概念沉淀质量和复用能力。

### 2.3 非目标（明确不做）

- ❌ 不做 DRM 破解、不做盗版书源、不做在线书城。
- ❌ 不做社交分享、书评社区、排行榜。
- ❌ P0/P1 不做扫描版 PDF 的 OCR（P2 评估）。
- ❌ 不做移动端 App（先做 DSH Web GUI 内的形态）。
- ❌ 不自建服务端账号体系；数据留在本机。
- ❌ 不做通用笔记软件（不与 Obsidian/Notion 竞争，只做"阅读中的概念"）。

### 2.4 关键决策记录

| 编号 | 决策 | 结论 | 影响 |
|---|---|---|---|
| D1 | 入口形态 | **独立 `conversation.view`**（`id: "reader"`），不寄生在右侧文档 tab | 阅读真正占满主区域；与 chat / trajectory 并列切换 |
| D2 | 概念卡触发 | **默认悬停出卡**；设置可改为「点击出卡 / 关闭」，悬停延迟可调（默认 150ms） | 不打断阅读是默认体验，误触用户有退路 |
| D3 | 书库归属 | **P0 直接读工作区目录**，但通过 `LibraryProvider` 抽象解耦；后期可平滑切换托管书库/其他来源 | 文档标识不依赖物理路径，换来源不丢标注 |

> 仍未定：产品名、导读分档、是否注入 DSH 主对话、是否移动端（见 §14）。

## 3. 设计原则

1. **阅读是主角，AI 是背景进程。** 任何 AI 能力都不得抢占版面、不得强制跳转、不得阻塞翻页。
2. **就地解释，而非跳转解释。** 解释出现在文本旁边，而不是新页面、新会话、新窗口。
3. **概念是资产，不是脚注。** 概念库跨文档存在，一本书只是它的一个"出现位置"。
4. **渐进呈现。** 先一句话，再直觉，再展开；不一次性糊一大段。
5. **克制地标记。** 只有**你标注过的**概念才会在正文里出现可交互标记；系统不替你下划线，否则满屏都是，阅读就毁了。
6. **可修正。** AI 的解释可编辑、可合并、可删除；用户永远拥有最终解释权。
7. **失败要体面。** 模型慢/失败时，先给占位与重试，不打断阅读。

## 4. 核心场景（用户故事）

### S1｜第一次遇到不懂的概念

> 我在读一本讲分布式系统的 PDF，第 3 章出现「线性一致性」。我选中它 → 点「解释」→ 行内出现一张小卡：「用一句话说：所有节点看到同一份历史」+ 本句语境 + 一个类比。我点了「收下」，它进了我的概念库。

### S2｜概念里还有概念（嵌套）

> 那张卡的解释里又出现了「因果一致性」。我直接在卡片里选中它 → 「再解释」→ 子卡浮出，面包屑显示「线性一致性 › 因果一致性」。我把两张卡的关系留了下来。

### S3｜下次在另一本书里再遇到

> 两周后读另一本书，正文里「线性一致性」下面有一条极淡的虚线下划线。我鼠标停上去 150ms，卡片浮出——不是重新生成，而是我上次收下的那张，还多了「本书第 7 章用法偏工程实现」。我继续读，没有离开这一页。

### S4｜读完整理成图

> 书读完了，我点「生成导读」。几分钟后，右侧浮出一张可折叠的思维导图：全书主旨 → 5 个部分 → 每章一句论点 → 关键概念挂在对应章节下。点任意节点跳回原文。

### S5｜读完想复习（P1）

> 我打开「概念库」，按"最近出现 / 掌握度低 / 同一父概念"筛选，5 分钟过一遍卡片。

## 5. 信息架构与核心对象

```
Workspace（工作区）
└── Library（书库，P0 即工作区内的文件集合）
    └── Document（文档）
        ├── Anchor（锚点：位置 + 引文）
        ├── Annotation（标注：高亮 / 笔记 / 概念链接）
        └── Guide（导读：大纲 + 导图 + 章节摘要）
Concept（概念，跨文档）
├── aliases / definition / intuition / context
├── parentId（嵌套） / related（关联）
├── occurrences[]（出现在哪些文档、哪句）
└── Q&A[]（追问记录）
```

**四个对象的关系**：`Annotation` 指向 `Document` 的一个 `Anchor`，并可挂到一个 `Concept`；`Concept` 之间可嵌套/关联；`Guide` 由 `Document` 派生，并引用 `Concept`。

### 5.1 概念卡的数据形态

```ts
type Concept = {
  id: string
  term: string                 // 规范词
  aliases: string[]            // 别名、缩写、中英对照
  definition: string           // 一句话定义（≤ 60 字）
  intuition: string            // 直觉/类比（≤ 120 字）
  context: string              // 首次遇到时的语境解释
  examples: string[]           // 1–3 个例子
  related: string[]            // 关联概念 id
  parentId?: string            // 嵌套的上级概念
  mastery: 0 | 1 | 2 | 3       // 未读 / 见过 / 懂 / 能讲（P1）
  occurrences: { docId: string; anchorId: string; quote: string }[]
  status: 'pending' | 'ready' | 'failed'
  source: 'agent' | 'user'     // 是否被用户编辑过
}
```

> 约束：`definition` 必须能在不展开的情况下读完；这是 hover 卡片的信息密度上限。

## 6. 关键流程

### 6.1 标注 → 解释 → 入库（主链路）

```
选中文本
  → 浮动 mini toolbar（高亮 / 笔记 / 解释 / 翻译 / 复制）
  → 点「解释」
  → 立即创建 annotation + concept(pending)，卡片占位「正在解释…」
  → Host 异步调用 LLM，产出结构化解释
  → concept 置 ready，卡片替换为内容，出现「收下 / 编辑 / 删除」
  → 收下后进入概念库，正文该词出现淡下划线（可 hover）
```

**关键要求**：从「选中」到「看到占位」≤ 100ms，用户不需要等模型。

### 6.2 嵌套概念

- 在任意概念卡的正文中选中一个词 → 卡片内浮出「再解释」→ 生成子概念，`parentId` 指向当前概念。
- 子卡以**层叠/分栏**方式打开，不覆盖父卡：面包屑 `父 › 子`，可逐级返回。
- 嵌套深度限制 3 层（防无限套娃），第 4 层折叠为「在概念库中打开」。

### 6.3 再次遇到（复用）

```
文档渲染 → 用概念库词表（含别名）做一次 Aho-Corasick 匹配
  → 命中的 span 加极淡虚线下划线（默认 #00000012，主题感知）
  → 鼠标悬停 150ms → 浮出已缓存的卡片（本地，无网络）
  → 未命中不标记（避免噪声）
```

**命中优先级**：完全匹配 > 别名 > 大小写/复数归一。**冲突**：同一 span 命中多个概念时，取"最近使用 / 层级最低"者，卡片内提供切换。

### 6.4 生成导读

```
点「生成导读」
  → 按目录/章节切块（每块 ≤ 8k token）
  → 每块 map：章节摘要（3 句）+ 核心论点 + 概念清单
  → 全局 reduce：全书主旨 + 5–7 个部分 + 阅读路线建议
  → 生成树状导图数据（可用 Markmap / 自绘 SVG 渲染）
  → 落库为 Guide，右侧抽屉展示
```

**要求**：可中断、可重试、可增量（只重算改动章节）；生成过程显示进度而非空白。

### 6.5 阅读与 Agent 联动（P1）

- 主 Agent 通过 `systemPrompt.section` 获得当前阅读上下文（书名、章节、当前段落）。
- 用户在聊天里问「这段什么意思」时，Agent 能直接引用当前阅读位置。
- 阅读器内的「追问」走独立轻量调用，不污染主会话。

## 8. 交互与视觉规范

### 8.1 布局

```
┌──────────────────────────────────────────────────────────────┐
│  顶部极简工具栏：目录 · 搜索 · 标注模式 · 翻译 · 导读 · 设置    │
├───────────────────────────────────────────────┬──────────────┤
│                                               │  右侧抽屉     │
│                                               │  ├ 目录       │
│              阅读区（≥ 60% 屏宽）              │  ├ 标注       │
│              正文居中，最大行宽 ~72 字符        │  ├ 概念       │
│                                               │  └ 导读       │
│                                               │  （可收起）    │
├───────────────────────────────────────────────┴──────────────┤
│  底部：进度条 + 页码/百分比（hover 才完整显示）                  │
└──────────────────────────────────────────────────────────────┘
```

- 工具栏默认半透明，滚动时淡出，向顶部移动时淡入。
- 右侧抽屉宽度 320–420px，可拖拽；收起后不占位。
- 阅读区左右留白随窗口自适应，保证行宽不超 75 字符。

### 8.2 选中态 mini toolbar

## 9. 技术方案（DSH 集成）

### 9.1 形态选型

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A. 原生插件**（推荐） | Host 插件负责存储/LLM/翻译/工具；Client 插件注册阅读 View | 复用主题、语言、快捷键、权限；数据留在本机；可被 Agent 调用 | 开发量最大 | ✅ 采用（D1） |
| B. iframe 嵌独立网页 | 起一个本地 Web 应用，塞进面板 | 前端自由 | 拿不到主题 token、语言、布局；与 DSH 割裂（官方实践明确不建议） | ❌ |
| C. 纯 Client 插件 + IndexedDB | 只做前端，不碰 Host | 最快 | 无法调用 LLM/翻译；数据无法被 Agent 使用；跨设备不可迁移 | ❌ 仅作技术预研 |

### 9.2 插件结构

一个 Bundle，两个半边：

```
dsh-reader/
├── package.json            # dsh.client 段 + ./client 导出
├── cordis.patch.yml        # 注册 Host 与 Client 行
├── index.js                # Host：storageDomain / llm / translator / tools / systemPrompt
├── client.js               # Client：阅读 View、右侧 tab、概念卡、导图
├── locale/                 # 中英文案
└── docs/DETAIL.md          # 插件详情页
```

### 9.3 挂载点（基于当前安装的实测 Slot 树）

| 用途 | 挂载点 | 说明 |
|---|---|---|
| 阅读主界面 | `conversation.view`，`id: "reader"` | 主区域一次只渲染一个 View；注册后与 chat / trajectory 并列切换（D1 已定） |
| 阅读器右侧面板 | `sidebar.right.pane.tab`，`key: "reader"` | 复用右侧栏的 tab 体系（现有 guide / document / terminal / files 同构） |
| 从文件预览进入阅读 | 在现有文档 tab 的工具区加「用阅读器打开」 | 挂 `sidebar.right.tab.document.actions` |
| 全屏专注 | `ctx.layout.openRightbar(true, true)` | Client `layout` 服务已提供 |
| 概念卡浮层 | 组件内自绘（React portal 到阅读容器） | 跨 slot 定位不稳定，且需随阅读滚动 |
| 设置 | `settings.section` | 独立设置页 |

**打开方式**：文件树 / 文档预览里的「用阅读器打开」→ 当前会话切到 `reader` View（成为主视图，可一键切回 chat）。同一本书再次打开时恢复上次阅读位置。

### 9.4 Host 能力映射

| 能力 | 使用的 DSH 服务 | 备注 |
|---|---|---|
| 概念/标注持久化 | `storageDomain.open(spec)` | 插件自有域，durable；导出到工作区 |
| 生成解释 / 导读 | `llm`（流式调用） | 复用用户已配置 provider；结构化 JSON 输出 |
| 翻译 | `translator.translate()` | 已有 provider 路由 |
| 给 Agent 用的工具 | `tools.register()` | 如 `reader_current_context`、`reader_search_concepts` |
| 阅读上下文注入 | `systemPrompt.section()` | 让主 Agent 知道"用户正在读第 3 章第 2 段" |
| 文档读取 | `workspaceFiles.readBytes`（Remote） | 按工作区权限读取，不越权 |

### 9.5 锚点方案（P0 核心难点）

统一采用 **W3C Web Annotation 双锚点**：

```ts
type Anchor = {
  // 位置锚点（快，但会漂移）
  position:
    | { kind: 'pdf'; page: number; rects: number[][]; charStart: number; charEnd: number }
    | { kind: 'epub'; cfi: string }
    | { kind: 'md'; start: number; end: number }
  // 文本锚点（慢，但稳）
  quote: { exact: string; prefix: string; suffix: string }
}
```

- **恢复顺序**：先位置锚点 → 校验 `exact` 是否一致 → 不一致则在 ±2 页/±2000 字符内用 `prefix+suffix` 搜索 → 再不行标记「原文可能已变更」。
- PDF 必须**有文本层**；扫描版检测到无文本层时提示"此文件暂不支持标注"。
- 重排（改字号）不重建锚点，只重算 rects。

### 9.6 解释管线

```
Client 选中 → 组装请求（词 + 句 + 段落 + 文档元信息 + 已有概念）
  → Host 查概念库（命中则直接返回缓存）
  → 未命中：llm.stream(schema)
  → 校验 JSON → 落库 → 推送 Client（订阅）
```

- 并发：同一词并发请求合并（single-flight）。
- 失败：指数退避重试 1 次，仍失败返回 `failed`，Client 显示重试。
- 成本：默认只发送命中句所在段落（≤ 600 字），不发全文。

### 9.7 数据存放

```
<workspace>/.dsh-reader/
├── concepts.json        # 概念库（P0 单文件，P1 分片）
├── docs/<fingerprint>/  # 每本文档的标注与导读
│   ├── meta.json
│   ├── annotations.json
│   └── guide.json
└── exports/             # 用户导出
```

- 同时写入 `storageDomain` 作为 durable 副本，崩溃可恢复。
- 文件指纹 = 路径 + 大小 + 首尾 4KB 哈希（防同名不同书）。

### 9.8 书库来源解耦（D3）

P0 的书籍来自工作区目录，但读取入口统一收敛到一个接口，避免路径假设渗透进标注与概念层：

```ts
interface LibraryProvider {
  id: string                    // 'workspace'（P0） | 'managed' | 'remote'
  list(query?: string): Promise<DocRef[]>
  open(ref: DocRef): Promise<{ bytes: Uint8Array; format: 'pdf' | 'epub' | 'md' }>
  watch?(ref: DocRef, onChange: () => void): () => void
}

type DocRef = {
  provider: string
  key: string        // 工作区为相对路径；托管书库为内部 id
  fingerprint: string // 内容指纹，跨来源稳定
}
```

- **文档主键用 `fingerprint`，不用路径**：换 Provider、挪目录、改名都不丢标注。
- P0 只实现 `WorkspaceLibrary`（走 `workspaceFiles` Remote，遵守工作区权限）。
- 后续加 `ManagedLibrary` 或第三方来源时，只需新增 Provider 并在设置里切换，概念与标注无需迁移。
- 打开失败（无权限 / 文件被删）返回明确错误码，阅读器给「重新定位文件」入口。

## 10. 非功能需求

- **可靠性**：概念库写入原子化（临时文件 + rename）；崩溃后自动恢复，最多丢最后一次操作。
- **离线**：已生成的概念卡离线可读；解释/导读/翻译需联网。
- **隐私**：默认只上传被解释的句段；设置页提供"发送内容预览"；不上传整本书。
- **可移植**：概念库导出为 JSON + Markdown，不锁定。
- **可访问性**：键盘全覆盖、屏幕阅读器可读、对比度达标。
- **国际化**：全部文案走 DSH locale 服务，中英双语。
- **可卸载**：插件卸载后不影响 DSH 其他功能；数据目录保留。

## 13. 风险与对策

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| PDF 锚点漂移（多栏、公式、动态页眉） | 高 | 标注错位，信任崩塌 | 双锚点 + 文本指纹 + 失效可见；先支持单栏正文，复杂版式降级 |
| 扫描版 PDF 无法标注 | 高 | 部分书不可用 | 明确提示；P2 接 OCR |
| EPUB 结构千奇百怪 | 中 | 渲染异常 | 仅支持 EPUB2/3 reflowable；FXL 明确不支持 |
| 概念泛滥，满屏标记 | 中 | 阅读被毁 | 只标记用户标注过的概念；默认关闭词表自动提示 |
| LLM 幻觉/解释错误 | 中 | 学错知识 | 引用原文、显示置信度、可编辑、可删除 |
| 模型慢导致体验断裂 | 高 | 用户放弃 | 占位 + 后台生成 + 重试；hover 只读本地缓存 |
| 成本失控 | 中 | 用户不愿用 | single-flight、缓存、默认只发段落、批量需确认 |
| 与 DSH 原生 UI 风格割裂 | 中 | 像外挂 | 只用主题 token、复用 slot、文案走 locale |
| 嵌套无限套娃 | 低 | 认知过载 | 限制 3 层，第 4 层转概念库 |
