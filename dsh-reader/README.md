# dsh-reader

**在 DSH 里读书、读论文、读文档；划词解释不离开原文，概念卡里继续追问、递归生长。**

- **不打断心流**：划词即解释、翻译、笔记，卡片贴着原文浮出，不切窗口、不离开当前页。
- **递归学习**：解释里遇到新概念，就在悬浮卡里继续追问、生成子卡；父卡保留、概念链可见，最多 3 层。
- **交给原生对话**：需要工具、联网或多轮推演时，把选区（含图 / 内联 SVG / MathML）交给当前会话，回答在书页旁流出来。

PDF / EPUB / Word（.docx）/ Markdown / TXT 都在会话主区域打开；核心是**概念卡**——划词解释后自动沉淀成一张留在原文旁边的卡片，记录定义、语境、例子和出处，跨书、跨论文复用「本书用法」。

![划词 → 解释 → 概念卡原地浮出](https://raw.githubusercontent.com/2019wakeup/dsh-reader/main/dsh-reader/docs/demos/01-select-explain.gif)

*选中一个词或短语，解释在原文旁边变成概念卡；需要工具或多轮推演时再交给原生对话。*

动图由 [`demo/`](demo/) 里的 Remotion 工程渲染，镜头与分镜见 [`demo/CAMERA.md`](demo/CAMERA.md)；划词解释、对话、长文档导读三条动线见[仓库首页](https://github.com/2019wakeup/dsh-reader)。

工作区自带三份试读素材：`示例-分布式系统阅读.md`、`示例-分布式系统.epub`、`示例-分布式系统.pdf`。

## 核心：概念卡与递归追问

- **划词即解释**：选中词或短语，工具条提供解释、翻译、笔记、高亮、复制；解释在卡片里完成，卡片贴在原文旁边。
- **留在原文**：卡片记录出现位置，点一下跳回原文；可以固定、拖动、编辑、合并，原文改动后还能迁移旧标注。
- **递归追问**：解释里遇到新概念，就在这张悬浮卡里继续对话追问，不用跳出阅读；新词还能就地生成子卡，子卡可以继续追问、继续生成（最多 3 层），父卡保留、概念链可见。
- **跨文档复用**：同一概念在第二本书或第二篇论文里再次遇到时，追加「本书用法」，原有解释保留。

## 安装

需要 dsh `>= 0.2.2-rc.5`（更早版本缺少对话接口，「问 AI」和「对话」页签会自动隐藏）。

### 普通用户：桌面端两步装好（推荐）

1. 下载安装 [DeepSeek 官方桌面端](https://www.deepseek.com/download/)，登录 DeepSeek 账号；
2. 侧栏 → **插件** → **添加插件**，输入 `@2019wakeup/dsh-reader@latest`，装好后在插件详情打开「启用」，重启桌面端。

> `@latest` 现在就是 0.14.0；如果习惯插件市场索引、或想固定版本，也可以按下面的步骤安装和更新。

### 也可以从插件市场索引安装

1. 插件页启用「实验性插件 → 自定义插件索引」；
2. 「发现 → 管理索引源」添加：
   ```
   https://raw.githubusercontent.com/2019wakeup/dsh-reader/main/plugin-market.json
   ```
3. 在发现页找到「砚读 · DSH 阅读插件」安装；以后有新版本会直接显示更新按钮。

### Windows 桌面端

Windows 10/11（x64）使用同一套桌面端与安装步骤；插件与阅读数据位于 `%USERPROFILE%\.dsh\profiles\desktop`，工作区数据仍在 `.dsh-reader/`。文件编码、路径分隔符、文件占用与快捷键已按 Windows 处理；不支持 `.doc` 旧格式，请先另存为 `.docx`。

### 开发者：命令行

```bash
dsh plugin --profile web add @2019wakeup/dsh-reader@latest
# 或从仓库安装本地目录：
dsh plugin --profile web add ./dsh-reader
```

<details>

- 添加插件时务必带 `@latest`，不带版本号对已安装插件是 no-op；
- pnpm 供应链策略 `minimumReleaseAge` 拦截新包时，等过窗口期或把包名加进 profile 的豁免清单。

安装后刷新页面，在任意会话顶部切换到「阅读」。

## 使用

- 书库：列出当前会话工作区的目录与可读文件。
- 划词工具条：解释 / 笔记 / 四色高亮 / 复制；点正文空白、滚动或 × 关闭。
- 点任意高亮可改色、写备注、删除；删除后 toast 可撤销，或按 ⌘Z / ⌘⇧Z 撤销重做。
- 概念卡可编辑（定义/直觉/语境/例子/别名/相关），标记为用户版本后模型不再覆盖。
- 概念抽屉显示「出现位置」，可跨文档跳回原文。
- 父子概念卡层叠显示，关闭子卡回到父卡。
- 设置抽屉可调字号/行距/悬停延迟/触发方式，重启保留；`?` 查看快捷键。
- 概念卡：定义、直觉、本书语境、例子、依据原文、相关概念；卡内可再选中词「再解释」（最多 3 层嵌套）。
- 追问：卡内就概念继续提问，可带相关概念上下文；同概念跨书复用时追加「本书用法」。
- 悬停：已收录概念在正文中显示虚线，停留 150ms 浮出卡片，不遮挡当前行。
- 导读（长书，可选「快速（篇级）」/「标准（段+篇）」成本档位）：PDF 读真实书签、按章分块、段→篇→全书两层归约；显示阶段进度、可停止；思维导图为「书→篇→节」；增量缓存；导出 PNG/SVG/MD。
- 目录：PDF 优先真实书签（缩进/页码/当前页高亮），无书签时按 20 页分组；EPUB/Word/Markdown 按章节/标题。
- 概念抽屉默认按当前书过滤，可切「全部」。
- 搜索：⌘F 全文搜索（Markdown/EPUB/Word 定位原文，Word 跨章；PDF 逐页提取跳页）。
- 翻译：Markdown/EPUB/Word 三态「关 / 段落对照 / 仅译文」；PDF 右侧译文抽屉按页对照；划词可即时翻译；可选中文/英文/日文，按段缓存不重复计费。Word 表格单元格不参与段落对照，避免译文撑破列宽。
- 阅读：浅色/深色/米黄主题、PDF 双页、方向键或 J/K 翻页；设置重启保留。
- 数据：JSON 导出/导入、标注 Markdown 导出、最近 5 份备份一键恢复；最近 10 次发送内容可在设置查看。
- 概念：支持合并（别名/出现位置随目标保留）；原文改动后按路径发现旧标注并一键迁移。
- 回答生成时正文会像主对话一样流式出现在气泡里；还没有正文时显示当前动作（正在读取文件/执行命令…）而不是空白，底部不再重复「生成中」横条。
- 读书对话：选中正文即可引用提问，回答流入抽屉「对话」页签（见下节）；消息里的图片会在气泡内直接显示，文档附件显示为文件名/类型/大小卡片。选区内含图片、内联 SVG 或 MathML 公式时，「问 AI」会把图形作为附件加进输入框、把公式源码写进引用。
- 抽屉：目录 / 标注 / 概念 / 导读 / 对话 / 设置；「对话」里提问与回答分列气泡，引用带书名与位置。
- 动效：划词工具条、概念卡、抽屉、对话新行、导图与跳转都有短促过渡；跳回原文时目标位置浮出一次性定位环。跟随系统「减少动效」；需要整体关闭时，给阅读器根节点加 `.rd-motion-off` 作为应急开关。

## 读书对话

用一直存在的底部输入框和原生智能体聊，不另开窗口、不换会话：

1. 选中正文一段，浮层点「问 AI」。原文带着书名、章节和位置进入底部输入框，抽屉自动切到「对话」页签。
2. 补上问题，回车发送。回答逐字流进「对话」页签，和原生对话页共用同一份会话记录。
3. 接着问：引用新的段落、在面板里选词再引用，或直接打字，都发生在同一个会话里。

- **角色区分**：用户消息右对齐、带「你」标签；助手回答左对齐、带「助手」标签；引用的书名和位置单独一行。
- **按轮聚合**：同一轮里模型可能分多步调用工具，面板把它们合并成一条回答，只显示这一轮的正文和一行「过程 · N」；纯工具步骤不会单独占行。点开「过程」先看到动作名（已读取文件、执行了命令…），思考内容还要再点一级才展开，和原生对话页的处理一致；需要完整轨迹时可「在对话页打开」。正在执行的操作合并成一行状态。
- **快捷追问**：浮层下拉提供「解释这段 / 举个例子 / 和上文什么关系 / 作者为什么这么说」。选中后引用和问句一起进入输入框，确认后再发送。
- **未读与跳转**：面板关闭时新回答点亮工具栏未读点；面板右上角「在对话页打开」可切到完整对话页。
- **宽度**：可拖拽，默认 420px，范围 320–720，随会话恢复。

宿主向智能体提供两个只读工具，让追问能落到原文：

- `reader_context`：当前书、章节、位置与最近一次上报的窗口标题；
- `reader_read`：读取最近一次上报的窗口正文（PDF 当前页前后几页，文本类书当前滚动位置附近），单次上限 8000 字，支持在窗口内搜索。

宿主不解析 PDF/EPUB 源文件，跨章或全书检索不在本版范围；想看更多内容，翻页或滚动后客户端会重新上报。

对话本身不写进插件数据：面板只读当前会话的对话快照，消息由 DSH 会话日志保存。阅读位置和窗口文本存在工作区 `.dsh-reader/context.json`（单会话 24000 字，最多 10 个会话），位置摘要同时写入 `store.json` 的 `reading` 字段。

## 数据

标注、概念、导读、译文保存在工作区的 `.dsh-reader/store.json`（v2：文档按内容指纹索引，改名/移动不丢），写入前自动备份最近 5 份到 `.dsh-reader/backups/`。

## 限制

- 扫描版 PDF（无文本层）不能标注。
- 固定版式 EPUB（FXL）不支持。
- `.doc` 旧格式、`.rtf`、`.wps` 不支持；Word 不还原分页、页眉页脚、分栏、文本框与页码。
- Windows 上不支持 `.doc` 文件关联与右键打开；请从书库或拖拽进入。
- 段落对照翻译、概念图谱、移动端尚未包含（见 1.0 PRD 决策）。
- 解释/导读/追问需要 DSH 已配置可用模型。
- 解释请求有 90 秒上限：模型迟迟不返回时会被中止并在卡片上显示超时（重试按钮可直接再试）。慢的渠道可以用环境变量 `DSH_READER_EXPLAIN_TIMEOUT_MS` 调高；失败原因会写进 `.dsh-reader/store.json` 的 `debug.lastError`。
- 读书对话依赖 DSH 提供的对话标准接口（`useChat` / `inputActions` / `openView`）。旧版本缺少这些接口时「问 AI」入口和「对话」页签自动隐藏，阅读不受影响。
- 「对话」页签只显示文字问答：工具调用与推理默认折叠成「过程 · N」，需要看细节时展开；审批、提问等需要操作的轮次仍要在对话页处理。
