## 1. 发布定义

1.0 = PRD §10 的发布标准全部打勾：

- 全部 P0 需求验收通过；
- 回归测试 ≥ 100 条全绿；
- 三本真实书 7 天 dogfood（中文 PDF / EPUB / 长 Markdown）；
- v1 → v2 迁移演练 3 次 0 丢失，恢复可用；
- 导出 → 空库导入内容一致；
- 键盘走查、双语走查、性能预算达标；
- 插件详情页、README、限制说明更新。

## 2. 工作流（每次改动都走这条流水线）

```
改代码
  → npm test            # 单元 + DOM 流程 + 回归
  → npm run build       # 生成 client.js
  → npm run eval        # 产品级 eval（7 项，见 §4）
  → 安装（plugin_manager remove + install）
  → 实时验证（接口 / 槽位 / 真实 store）
  → 手动验收清单（涉及 UI 时）
  → 提交 + 账本记录
```

命令（在 `dsh-reader/` 下）：

```bash
npm test          # node --test test/*.test.mjs
npm run build     # node scripts/build-client.mjs
npm run eval      # node eval/run.mjs（失败退出码 1）
npm run migrate:rehearsal   # 3 次 v1→v2 迁移演练
npm run eval:visual         # 视觉 eval（无头 Chrome + 10 张基线截图）
npm run release:check       # 10 项发布门禁（测试/eval/视觉/迁移/回环/资产/文档/演示书）
```

**门禁**：`npm test`、`npm run eval`、`npm run eval:visual`、`npm run release:check` 必须同时全绿，才允许安装与提交。任何一项红，任务不算完成。

## 4. Eval 矩阵

| Case | 验证什么 | 阈值 |
|---|---|---|
| `anchor.spanning` | 跨粗体/代码的高亮不丢 | 丢失 = 0 |
| `anchor.unresolved` | 原文变更时能报告失效 | 必须报告 |
| `concept.boundary` | `AI` 不在 `EMAIL` 内匹配 | 假阳性 = 0 |
| `markdown.perf` | 140KB Markdown 渲染 | ≤ 150ms |
| `fingerprint.stability` | 指纹稳定且对内容敏感 | 通过/不通过 |
| `migration.v1` | v1 → v2 不丢标注与概念 | 丢失 = 0 |
| `bundle.smoke` | `client.js` 可加载并注册视图 | 必须注册 |
| `guide.parse` | 章节/全书 JSON 解析与上限 | 必须解析 |
| `mindmap.layout` | 树布局节点与边完整 | 必须完整 |
| `carddrag.bounds` | 短卡可到下半屏、长卡按高度受限 | 边界正确 |

## 6. 数据安全协议

1. 任何数据结构变更（如 v1→v2）必须：先备份 → 迁移 → 校验 → 可回滚。
2. 迁移失败不得覆盖原文件；界面报错并保留原文件。
3. 真实 store 迁移前手动复制到 `/tmp/store-v1-backup-*.json`。
4. 每次写入前自动备份，保留最近 5 份（`.dsh-reader/backups/`）。
5. 合并类操作（概念合并、别名）必须可撤销或可导出。

- [ ] 概念库点「出现于 N 处」跳回原文（Task 4 后）。
- [ ] 编辑概念定义，保存后重开仍是自己的版本（Task 5 后）。
- [ ] 父子卡同时可见，关闭子卡回父卡（Task 6 后）。
- [ ] 设置改字号/延迟，重启后保留（Task 7 后）。
- [ ] 输入框内按方向键不翻页（Task 7 后）。

## 8. 变更与记录

- 范围变更：只改 PRD 决策记录，并说明对里程碑的影响；未记录的变更不执行。
- 每个任务完成：更新账本 `.superpowers/sdd/dsh-reader-v0.2/progress.md`，记录提交号、测试结果、偏差与裁决。
- 每个里程碑完成：在 PRD §11 更新状态，并跑一次真实书籍演练。
