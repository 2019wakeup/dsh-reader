# 砚读：亮点与技术设计

> 面向开发者与深度用户的版本。产品功能总览见 [README](../README.md)。

## 一、长书阅读的四个工程问题

一本 500 页的非虚构作品，会同时遇到四类问题：

1. **结构不可靠**：PDF 书签可能损坏、缺失，甚至所有条目都指向同一页；
2. **上下文装不下**：整本几十万字，任何单次模型调用都放不下；
3. **成本不可控**：按页、按段直接调用模型，一次导读可能是几百次调用；
4. **阅读状态易碎**：滚动、重渲染、换书、改文件，都可能让标注和卡片错位或消失。

砚读把这些问题拆成四层：**结构恢复 → 分层归约 → 缓存/并发 → 可验证的界面**。

## 二、结构恢复：先相信书签，再相信排版

### PDF

1. 读内嵌书签（`getOutline`），把命名目标/引用目标解析成页码；
2. **校验书签可信度**：页数重复率过高、顺序回退、页码越界都判为不可信；
3. 不可信时按**页面排版恢复章节**：取每页文本行，比较字号中位数，寻找显著更大的标题行，过滤页码、图注、表注；
4. 仍失败则按页组切分，并如实展示覆盖范围。

实测某本 523 页中文书：26 条书签中 25 条指向同一页 → 判定损坏 → 排版恢复出 23 个章节，覆盖 3–521 页。

### EPUB / Markdown

EPUB 用 spine + nav 章节；Markdown 用标题层级。两者都输出同一份中间结构：

```text
{ toc: [...], chapters: [...], parts: [...], sections: [...] }
```

`toc` 用于目录导航，`parts` 是篇级归约层，`sections` 是段级摘要单元。

## 三、分层归约：把“整本书”变成有界的工作量

### 两种档位

| | 快速（篇级） | 标准（段+篇） |
|---|---|---|
| 段级摘要 | 每篇采样一段 | 每篇按页预算切段 |
| 篇级归约 | 单段篇直接复用段摘要 | 多段篇再调一次模型 |
| 全书主旨 | 篇摘要 → 主旨 | 篇摘要 → 主旨 |
| 27 章书调用量 | 约 27 次 | 约 73 次 |

关键设计是**单段篇复用**：Host 发现某篇只有一个 section 时，直接把该 section 的摘要提升为篇摘要，不再发起模型调用。这让快速档的调用量≈篇数+1。

### 采样策略

长章节取**头 70% + 尾 30%** 的样本，中间标注“省略”，让摘要覆盖章节结尾，避免只总结开头。

### 缓存

- 每个 section 以内容 SHA-1 为 key；
- 每篇以成员 section 的 hash 组合为 key；
- 整份导读命中缓存时，**0 次模型调用**；
- 快速档的 section 文本与标准档不同，各自独立缓存。

## 四、解释与翻译：单飞、低推理、按内容缓存

### 解释路由

- **quick**：紧凑 JSON（定义/直觉/例子），`maxTokens 900`，选择模型支持的最低推理强度；
- **full**：完整字段，`maxTokens 1600`，卡片上「深入解释」按需触发，合并结果不覆盖用户手改版本；
- **cached**：概念已存在直接返回，0 调用；
- 同词并发 **single-flight**：两个读者同时解释同一个词，共享一次模型调用（按 workspace + term + depth 去重）；
- 每次解释带 90 秒死线，超时返回 504 并写入 `debug.lastError`，客户端等待 100 秒后兜底。

实测：快速 2.39s / 深入 4.70s / 缓存 0.00s。

### 翻译

- 默认英译中；原文语言可选自动检测，目标语言支持中文、English、日本語、한국어、Français、Deutsch、Español、Русский、Português；
- 共享 `blockHash`（FNV-1a + 长度）在客户端与 Host 两侧一致；
- Markdown/EPUB 通过 IntersectionObserver 只把当前视口（含 240px 预取）内的段落加入队列；滚动产生的新段落继续入队。队列每批 8 段 / 3200 字符，译文逐段回填，不阻塞首屏；
- 仅译文模式同样按可见区域渐进，未完成的段落保留原文，避免整页空白；
- 译文持久化到 `docs[docKey].translations[lang]`，同一段不重复计费；代码块不参与翻译；
- PDF 按页提取文本块，按 8 段分批请求，抽屉里的译文逐批出现，不必等整页完成；
- 选中文字即时翻译沿用同一组源/目标语言。

## 五、数据模型：内容指纹 + 迁移 + 备份

```text
store.json (v2)
├── revision          写入递增，客户端据此丢弃过期快照
├── prefs             阅读偏好 / 语言 / 导读档位 / 模型
├── concepts          概念卡片：定义、直觉、语境、例子、出现位置、QA、跨书用法
├── docs[docKey]      内容指纹 → 路径、标注、位置、导读、译文
└── debug.lastSent    最近 10 次发送内容摘要
```

- `docKey = sha256(size + 前 4KB + 后 4KB)`：改名/移动不丢；
- v1 → v2 自动迁移，迁移前备份；
- 写入走 per-workspace 队列，避免“解释/翻译/位置保存”并发互相覆盖；
- 备份保留最近 5 份，损坏时自动回退到最新可读备份；
- 导入走同一写队列，并有数量确认与恢复出口。

## 六、界面可靠性：视觉门禁与边界定位

- 阅读区位于 DSH 主区域；浮窗（概念卡、编辑卡、迷你菜单、译文卡）按**阅读区边界**定位：优先侧边、其次上下，窄屏缩宽，resize 重新计算；
- 术语与高亮标记采用**签名幂等**：概念/标注集合没变就不重建 DOM，避免鼠标下的节点被替换导致悬停卡闪断；
- 视觉 eval 用无头 Chrome + mock 数据 + 真实渲染：
  - 97 项断言、19 张基线截图；
  - 覆盖书库、正文、概念卡、标注编辑、笔记弹窗、导读、导图、设置、搜索、PDF、EPUB、仅译文、冲词翻译、英文界面；
  - 像素差阈值 0.3%，动画在基线中关闭，保证可复现。

## 六点五、翻页与阅读进度

- PDF：页码输入框可跳转（Enter 确认、Esc 还原）；方向键/空格翻页；Home/End 首尾；相邻页对象预取降低翻页等待。
- Markdown/EPUB：方向键/空格按 85% 视口滚动；滚到章尾再按进下一章、章首回上一章；Home/End 到文档首尾。
- 顶部细进度条：PDF 按页、EPUB 按章 + 章内滚动、Markdown 按滚动比例。
- 键盘细节：只有输入框会拦截方向键，按钮聚焦时方向键仍然滚动；空格在按钮上保留原生激活。

## 六点六、侧栏滚动与正文独立

- 目录 / 标注 / 概念 / 导读 / 设置各自有独立滚动容器；每个 tab 记住自己的滚动位置；
- 键盘方向键在侧栏内滚动侧栏，不会带动正文；
- 正文与侧栏都设置 `overscroll-behavior: contain`，滚到边界不会把滚动链传给对方或页面；
- 视觉门禁用「滚侧栏正文不动」「滚正文侧栏不动」「方向键在侧栏内」「切 tab 恢复位置」四项断言锁定。

## 六点七、导读与导图的跳转和缩放

- 导读摘要持久化 `page` / `chapter`：PDF 点条目跳页、EPUB 点条目跳章、Markdown 按标题匹配（兼容编号后缀）；
- 单段篇在导读列表与导图中合并成一个节点，避免「篇」和唯一「段」重复；同一章的分片在导图中作为章节点的可展开子节点，标签为「分片 1/2/3」（PDF 带页码），默认折叠、可逐层钻取；
- 导图默认折叠到章级，节点标题两行显示，首次打开自动适配侧栏宽度；放大后可拖拽平移，点击节点在导图上方显示摘要/要点并可跳回原文；支持全屏与 Esc 退出；
- 拖动平移只在指针移动超过阈值后才 `setPointerCapture`，否则会把节点 click 一并吞掉；三角热区扩大、节点文字不拦截点击；
- guideTree 只随指南内容或书名变化，页码/结构探针等文档状态更新不会重置导图的选中节点与折叠状态，避免点击分片时摘要面板闪现关闭；
- 全屏用固定层实现，提供明确的「× 退出全屏」、捕获阶段 Esc 和离开导图自动复位；
- 导图缩放改为「放大画布 + 视口滚动」，不再裁切；1:1 复位；导图视图自动使用更宽的侧栏；
- 侧栏用 `min-width:0` 约束，画布溢出只在侧栏内部滚动，不会把侧栏撑宽。

## 六点八、Markdown 渲染

- 块级：ATX/Setext 标题、段落（软换行保留、两个空格或反斜杠为硬换行）、围栏代码（```/~~~、语言类名）、引用（递归块）、有序/无序/嵌套/任务列表、GFM 表格（对齐、单元格内 code、转义竖线）、分隔线；
- 行内：代码 span、加粗/斜体/删除线、链接与自动链接、图片、HTML 实体解码、反斜杠转义；原始 HTML 全部转义，链接只放行 http(s)/mailto/锚点；
- 图片：http(s)/data:image 直接加载；相对路径按文档目录解析后走 `/api/file`（Host 增加图片 MIME），无法解析时降级为 alt 占位；表格统一包在可横向滚动的容器里；
- 视觉门禁覆盖表格、对齐、任务列表、嵌套列表、语言类名与相对路径图片。

## 六点九、宿主布局与模型调用可靠性

- DSH 的 `conversation.view` 用内容撑高包裹层，`height:100%` 会塌成 `auto`；阅读器向上测量最近裁剪/滚动祖先的可见高度，把根节点钉成像素高度，并监听 resize / ResizeObserver。测量时扣除滚动容器底部 sticky/fixed 覆盖层（DSH 的 composer 输入框），否则根节点会把输入框高度也算进阅读区，宿主 scrollBody 多出第三层滚动条。`eval/layout-host.mjs` 用真实宿主 CSS 链、composer 与真实 `client.js` 做 6 项探针（含「外层不产生滚动条」），纳入发布门禁。
- 解释调用有 90s 死线（`DSH_READER_EXPLAIN_TIMEOUT_MS` 可调），超时返回 504；quick/full token 预算分别 900/1600；失败写 `debug.lastError` 与最近 5 条 `debug.errors`。客户端等待 100s 并有本地化超时文案。
- 死线定时器必须保持引用（不能用 `unref()`），否则进程可能在超时前退出；路由测试专门覆盖停摆流与单飞释放。

## 八、取舍与边界

- **先保证读得下去，再追求炫技**：浮窗不遮当前词、翻译不打断滚动、导读可停止；
- **成本可见**：批量前显示段/篇/token 估算，生成中可停止；
- **数据优先于平台**：本地 store、可导出、可迁移，是这个插件与“网页 AI 阅读器”的根本区别；
- **不假装全能**：扫描版 PDF、FXL EPUB、移动端、代码块翻译都不在 1.0 范围内，文档里明确写出来。
