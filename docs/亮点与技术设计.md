# 砚读：设计说明

> 这份文档解释砚读为什么长成这样。产品总览见 [README](../README.md)。

## 一、核心目的：阅读保持连续，问题在原文处解决

读一本难书时，打断阅读的往往来自工具的使用方式：遇到一个词，切到聊天窗口；得到一个回答，再切回来；读到下一段发现还需补充，于是开一个没有上文的新会话。等回答结束，读者已经离开了原来的段落。

砚读把「阅读连续性」当作第一目标。具体到设计上：

- 解释、翻译、笔记都在选区旁以浮层出现，正文停留原位，焦点仍在阅读区；
- 卡片、菜单、编辑器的位置以阅读区边界为准，正文滚动后仍能找到来源；
- 悬停卡片有进入宽限与固定状态，鼠标从词移到卡片时保持展开；
- 侧栏与正文各自滚动，导读、目录、概念库保留自己的位置，正文停留原处；
- 阅读器只占宿主给它的可见高度，正文和侧栏是仅有的两个滚动容器。

第二目标是**就地闭环**：所有问题都在当前文本附近产生，也在当前文本附近解决。解释、追问、父子概念、翻译、标注都以当前选区或当前页为锚点，在当前位置完成。

第三目标是**沉淀**：解决过一次的问题应该留下来。解释自动成为概念卡，记录出处，可以在同一本书、下一本书里继续复用。

## 二、概念卡：核心对象

概念卡在阅读流程里承担主要数据对象的角色。

### 触发

- 用户选中文字后，工具条出现在选区旁；
- 「解释」走快速档：返回定义、直觉、例子，通常 2–3 秒；
- 需要更完整的语境时，点「深入解释」，补齐原文语境和更多例子；
- 解释失败会展示错误卡和重试入口，正文回到可继续阅读的状态。

### 卡片形态

概念卡按阅读区边界定位，优先显示在文字侧边，窄屏时收缩；卡片可以：

- 固定，跟随当前滚动位置；
- 从标题区拖动位置；每张卡有独立 hover 区和拖动偏移，叠加时最上层拦截点击、下层响应露出区域；纵向范围按卡片实际高度计算，短卡可以拖到屏幕下半部，长卡按自身高度受限；
- 编辑字段（定义、直觉、语境、例子、别名、关联概念）；
- 从卡片打开概念库并定位到它；
- 合并到另一个概念；
- 删除；
- 在卡片里直接追问；卡片内选中文字后的「再解释」浮层会短暂显示后自动消失。

长卡片使用 480px 高度上限、细滚动条和粘性标题；滚动时词条、图钉和关闭保持可见。固定/取消固定放在卡头图钉图标里，动作区只保留阅读相关操作。

### 原文锚定

概念会记录出现位置：文档内容指纹、章节/页码、引用文本和出现序号。点击出处可以回到原文；文档改名或移动后锚定仍然有效。原文变化后，旧锚点会提示并支持迁移。

### 父子概念

解释里遇到的新词可以在同一张卡上继续生成子概念。概念链最多三层，卡片顶部显示链路。派生词在当前解释上继续展开，同一段落保持完整。

### 跨书积累

同一个概念在第二本书里出现时，系统保留旧解释，并追加「本书用法」。概念库支持按当前书/全部筛选，读者可以看到一个词在不同文本中的含义变化。

### 持久化

概念写入 `docs[docKey]` 之外的工作区 store：

```text
concepts[conceptId]
├── term / aliases / related
├── definition / intuition / context / examples
├── depth: quick | full
├── occurrences[]: docKey, chapter, page, quote, occurrence
├── contexts[]: docKey, note        # 跨书用法
├── qa[]: question, answer, web
└── parentId                        # 父子链
```

写操作经过 per-workspace 队列，避免解释、翻译、位置保存并发覆盖；store 自动保留最近 5 份备份。

## 三、阅读连续性如何实现

概念卡只是核心，连续性还需要界面层配合。

- **浮窗定位**：卡片、编辑卡、迷你菜单以阅读区为边界；窄屏缩宽，resize 重算。
- **悬停稳定**：术语与高亮标记按内容签名做幂等更新，集合没有变化时复用现有 DOM；悬停卡有 600ms 进入宽限和 `:hover` 检查。
- **键盘路径**：书库、抽屉、术语、高亮可聚焦；方向键与 Home/End 滚动，抽屉内滚动只作用于抽屉。
- **侧栏独立**：目录、标注、概念、导读、设置各有滚动位置；正文与侧栏各自保留滚动状态；所有侧栏共用可拖分隔条，普通侧栏和导图侧栏分别记忆宽度；导读列表与导图分别记忆抽屉滚动位置，进入导图回到顶部。
- **宿主布局**：DSH 的 `conversation.view` 用内容撑高包裹层，百分比高度会塌成 auto。启动时测量最近裁剪/滚动祖先的可见高度，扣除底部 sticky 输入框，把根节点钉成像素高度。
- **滚动边界**：正文和侧栏都设置 `overscroll-behavior: contain`，滚动到尽头即停在本面板。

## 四、导读与导图：先理解结构，再给骨架

长书导读先解决结构，再解决上下文长度。

### 结构恢复

PDF 优先读内嵌书签；书签可信度低时按排版恢复章节：

1. 取每页文本行，比较字号中位数；
2. 寻找显著更大的标题行，过滤页码、图注、表注；
3. 仍失败则按页组切分，并展示覆盖范围。

实测一本 523 页中文书，26 条书签中 25 条指向同一页，最终恢复 23 个章节，覆盖 3–521 页。

EPUB 用 spine + nav，Markdown 用标题层级，最终都落到同一份结构：

```text
{ toc: [], chapters: [], parts: [], sections: [] }
```

### 分层归约

| | 快速（篇级） | 标准（段+篇） |
| --- | --- | --- |
| 段摘要 | 每篇采样一段 | 每篇按页预算切段 |
| 篇摘要 | 单段篇复用段摘要 | 多段篇再调一次 |
| 全书主旨 | 篇摘要归约 | 篇摘要归约 |
| 27 章调用量 | 约 27 次 | 约 73 次 |

长章节取头 70% + 尾 30% 的样本，中间标注省略。每段按内容哈希缓存，未变化的段落直接命中缓存；生成过程显示进度、可停止。

### 导图

导图默认只显示「书 → 篇/章」，章节点可展开为分片子节点；分片标签带摘要首行（PDF 带页码）。支持缩放、拖拽平移、全屏、1:1 复位和导出。点击节点在导图上方显示摘要、要点与「跳到原文」。

## 五、翻译：围绕当前视口工作

翻译同样服务阅读连续性。

- 默认英译中，原文语言与目标语言都可选；原文支持自动检测；
- Markdown/EPUB 用 IntersectionObserver 只把当前视口附近段落加入队列，队列每批 8 段 / 3200 字符；
- 滚动产生的新段落继续入队，译文逐段回填；仅译文模式也按可见区域渐进；
- PDF 按页提取文本块，每批 8 段请求，抽屉中的译文逐批出现；
- 代码块保留原文；
- 译文持久化到 `docs[docKey].translations[lang]`，按目标语言分别缓存；
- 划词翻译与段落翻译共用同一组源/目标语言。

## 六、数据与可靠性

- `store.json` 以内容指纹（大小 + 首尾 4KB 的 SHA-256）索引文档；
- v1 → v2 自动迁移，迁移前备份；
- 写入串行化，失败回退到最近可读备份；
- 解释调用有 90 秒死线，超时返回 504，失败写入 `debug.lastError` 与最近 5 条错误；
- 导出、导入、恢复都有 UI 入口；
- 阅读数据保存在工作区，模型调用使用 DSH 当前配置。

## 八、使用场景

### 论文与研究报告

阅读单位是术语、段落和上下文。术语解释贴着选区出现，概念卡记录页码/章节与引用，回到原文可以直接定位。读下一篇论文时，同一概念追加「本书用法」，便于比较不同论文的定义差异。英文论文使用按视口推进的段落翻译；划词依赖 PDF 文本层，扫描件和公式区域暂不支持。

### 技术文档与规范

API、协议、框架文档里，术语经常在具体语境中改变含义。解释卡、标注和笔记都停留在文档上；翻译保留代码块原文，避免标识符被改写。目录、搜索和侧栏用于在长文档中往返定位。

### 进入新领域

先用导读和导图建立篇/章骨架，再逐章阅读。遇到术语生成概念卡，派生词继续生成子卡，概念链留在当前卡片顶部。概念库支持按当前书或全部查看，同一领域的多本书可以各自保留「本书用法」。

### 系统学习与长期积累

概念卡保存定义、直觉、语境、例子、出处和追问记录，支持编辑、合并与导出 Markdown/JSON；标注同样可以导出。课程材料、行业报告和技术书可以按同一流程处理：阅读中解决问题，读完后留下可检索的概念和标注。

## 九、取舍与边界

- **阅读先于功能密度**：浮窗贴着当前词，菜单与正文共用一处焦点；内容优先留在原文旁。
- **概念先于会话**：解释结果进入概念库，随工作区保存。
- **可解释的成本**：导读提供两档；翻译只做可见区域；解释有死线和失败记录。
- **当前范围**：桌面阅读、文本层 PDF、EPUB/Markdown；扫描版 PDF、FXL EPUB、移动端和代码块翻译暂未覆盖。
